# OfferProof — 2–4 minute demo outline

1. **0:00–0:25 Problem.** A student receives a plausible job message. Standard warning lists help, but the immediate question is which claims can be checked without trusting the sender's own links.
2. **0:25–1:00 Payment case.** Choose “Payment request”; show the quoted text, red flag and the word “unverified.” Never say that all scam messages have this signal.
3. **1:00–1:40 Plausible case.** Choose “Plausible offer”; show that no listed signal still means unverified. An actual job opening would not establish who sent this message.
4. **1:40–2:15 Identity request.** Choose “Identity request”; walk through the pause and independent-channel next step.
5. **2:15–2:45 Evidence.** Record a listing found through the message and another found independently. Explain the provenance distinction and that neither authenticates the sender.
6. **2:45–3:10 Response.** Select a password disclosure and show recovery actions. Then show one live AI extraction when a free Groq key is configured; state if only fallback works.
7. **3:10–3:30 Limits.** This prototype neither authenticates senders nor guarantees safety. The 12 invented cases are a development smoke set, not an impact study. Close with the next evaluation: blinded baseline and outside usability sessions.

Record screen and voice separately if useful. Never show the API key, personal recruiting messages, or private notes in the recording.
